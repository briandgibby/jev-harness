# Jev Orchestration Harness execution brief

## Mission

This packet directs orchestration and the local browser fixture. The [standalone Choice execution brief](../../agent_prompt.md) governs the earlier API pilot; this brief extends that adapter through the canonical orchestration PRD/PRS rather than replacing the pilot's evidence or requirements.

Build and test the command-line Jev Orchestration Harness in the repository root. The authorized outcome is a fixture route → coding-model patch → trusted verification path, plus at least two distinct pinned local coding-model registrations and a watched Intel Arc Pro B70 inference path through OVMS 2026.4.0 on Windows. Jev performs one bounded typed routing judgment at a time. It stays in shadow mode until held-out routing evidence supports promotion. No model connects components, authorizes tools, or declares tests green. (JOH-1–JOH-8)

Both post-pin dry-runs and fast installed-root `verify` passed; fast install/serve were watched, while the strong script install/serve path remains untested. `tools/prepare_verifier.ps1` ships dry-run/install/verify for the pinned Docker image; dry-run/verify passed on this host. The verifier runs protected evaluator code in the pinned Docker Python 3.14.6 slim image with no network, read-only root/checkout, all capabilities dropped, and no credential environment. Retain the failing-then-passing regression and a new watched live run before asserting JOH-5 completion integrity; old records are rejected on replay. 6. Review `README.md`, canonical PRD/PRS, checklist, and actual files before handoff. Finish [walkthrough.md](walkthrough.md) only from observed files/output. Run the packet validator with `--strict --require-walkthrough` after the final edits. Leave JOH-8 open until a held-out routing comparison runs. No commit, push, deployment, schedule, or broad unattended run is authorized by this brief. (JOH-1–JOH-8)

The first live scope is one generated task, one coding-model attempt, bounded output/time/path effects, and optionally one watched Jev shadow call after source admission. ## Verification and deliverables

From the repository root, run `python --version` and `python -B -m unittest discover -s tests -p 'test_*.py' -v` after code settles. Then run the exact shipped commands in the [plan's verification table](implementation_plan.md#verification-commands-and-evidence-plan): fresh `init`, `demo`, `dry-run`, setup-script dry-run and watched setup, `local_model.py probe`, one watched `run --mode live`, `inspect`, and `replay`. Retain each command's unedited output. Run `python -B orchestrate.py --help` and `python -B local_model.py --help` to verify registration. Add negative checks for forbidden egress, path traversal, model mismatch, missing runtime/device, failed or bypassed tests, and incomplete audit. The coding CLI has no `doctor`, `smoke`, or `generate`; the separate computer-use CLI ships `doctor`, and `ui_fixture.py` ships `generate`. (JOH-1–JOH-7)

The deliverables are a usable CLI, two pinned locally exercised coding models, a bounded live coding attempt with independent check evidence, explicit Arc Pro B70 inference evidence or an honest incomplete gate, updated operator instructions, a reconciled packet, and an evidence-backed walkthrough. A smoke run is not a coding-quality benchmark; the [held-out study](../../coding-decision-study.md) controls any later Jev-superiority claim. (JOH-3, JOH-5, JOH-8)
