# Coding Decision Study

Status: proposed protocol, **not an executed coding benchmark**. This document owns the study design, treatment definitions, outcomes, and analysis rules. The eventual versioned task manifest will own task facts and adjudications; repository commits and unedited test output will own observed behavior. [RESEARCH.md](RESEARCH.md) owns the broader Jev adoption rationale, and [LIVE_RESULTS.md](LIVE_RESULTS.md) owns the earlier, non-coding synthetic pilot.

## Question and boundary

**Primary question:** Can Jev route coding tasks among a fixed set of coding models at lower all-in cost than an LLM router while preserving independently verified task completion?

**Secondary questions:** Can Jev usefully classify the cause of a failed test run, choose among fixed feature plans, or identify missing test coverage? These are separate experiments with separate labels and outcomes. A positive routing result does not validate the other uses.

The orchestrator is ordinary code. It calls the chosen coding LLM, Jev when assigned, and the test runner through direct interfaces. Jev emits a typed observation; versioned code owns routing, bounds, authorization, execution, and reporting. Jev never writes code or declares tests green. TypeSafe explicitly describes Jev as a decision model rather than a coding-agent replacement. [Coding-agent guidance](https://docs.typesafe.ai/introduction/coding-agents), [intent routing](https://docs.typesafe.ai/patterns/intent-routing).

## Four decision studies

| Study | Frozen input available at decision time | Gold or downstream outcome | Main error to expose |
| --- | --- | --- | --- |
| Model routing (primary) | User task, pre-change repository facts, allowed model registry | Independent evaluator's required and held-out tests, plus actual all-in cost and time for each route | Sending a hard task to an inadequate model or paying for a router that adds no value |
| Failed-test triage | First failing command and a sanitized excerpt of its unedited output; no later diagnosis | Cause established by controlled reruns, baseline comparison, environment checks, and blinded adjudication | Calling a real regression “flaky” or “environmental” |
| Feature-plan selection | Same two or three frozen plans from one plan generator, requirements, and pre-change repository facts | Blinded plan review and the outcome when the same coding agent implements the selected plan | Favoring a plausible but infeasible or requirement-incomplete plan |
| Test-gap detection | One acceptance criterion and its proposed tests | Blinded requirement-to-assertion review, withheld regression tests, or seeded faults | Missing a material untested behavior while calling coverage complete |

Exact properties—test exit codes, changed paths, file existence, arithmetic, dependency edges, and policy prohibitions—are computed in code. Jev is asked only the residual semantic question. Its published limitations include multi-step reasoning, numbers, large noisy state, adversarial content, and Choice option-order effects; deliberately include these as negative-control slices. [Jev 1.13 limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13).

## Task corpus and labels

The target population is **coding assignments in the user's active repositories**, not all software development. Inventory eligible issues and requests from a declared time window before sampling, record exclusions and duplicates, and sample within the strata below. Use recent, reproducible tasks from at least three repositories if available; report SignSense-specific and cross-repository results separately when sample sizes permit. Freeze aggregate stratum weights from the observed task mix *before* held-out outcomes are known. If no trustworthy task-mix census exists, report only stratum-specific estimates and make no aggregate or general-coding claim. Target 60–100 held-out tasks for an initial exploratory end-to-end comparison; final confirmatory sample size is determined from pilot task-level variance and the smallest worthwhile effect, before examining held-out results. Sixty to one hundred pairs cannot establish small noninferiority margins reliably. Prefer private tasks with known base commits and independent acceptance criteria over a public leaderboard that may have test-oracle or contamination problems.

Stratify before sampling: routine edit, contained bug, cross-file feature, failing-test repair, setup/environment failure, and ambiguous or high-risk request. Include short and long/noisy context, close competing routes, no-fit cases, and text that attempts to steer the classifier. Keep related issues, duplicate bug reports, and revisions of the same feature in one split. Do not tune on the held-out tasks.

Each task record identifies one base commit, exact setup and required-test commands, task instructions, allowed paths/tools, resource caps, a **frozen approved predecision summary and feature record**, and evaluator-only acceptance tests. All routing arms receive that same summary and feature record; none gets privileged metadata or later diagnosis. For bug fixes, record the pre-change command that fails and require the same command to pass after the change; exclude an unreproducible bug from this stratum until a diagnostic record can catch it. For features, run the existing baseline suite and establish new acceptance checks before agents see the task. An independent evaluator retains withheld tests and final fixes; routers and coding agents never receive them. Two reviewers resolve ambiguous acceptance criteria before treatment runs. Store adjudications in the manifest, with disagreement and `unknown` preserved rather than forced into a positive label.

The manifest is the canonical source for task metadata and labels. Generated worktrees, sanitized decision records, and reports are derived and rebuildable. Never include credentials or raw secret-bearing source in Jev state: the existing harness persists its complete input and request before sending the request to TypeSafe. [Harness audit behavior](../jev_harness.py).

## Primary paired comparison

For each held-out task, start every arm from the same commit in a fresh isolated checkout, with fresh agent context. Keep the available coding models, model versions, route-to-model map, coding prompt, tools, required checks, fallback rule, wall-time cap, token cap, and execution budget fixed. Give the rules router the same frozen predecision information as the model routers. **Only the route decision changes.** Randomize arm order within time blocks to reduce provider-time and machine-load effects. Mask arm names for human patch review. If affordable, repeat a prespecified subset with fresh agent contexts to estimate coding-run variation separately from routing variation.

The candidate finite routes are `routine_local` (lower-cost model), `contained_debug` (standard model), `cross_component` (stronger model), and `unclear` (the common escalation path). A task touching credentials, authorization, or an explicitly protected subsystem follows a hard code rule before any semantic routing. Exact model IDs and route mapping are configuration values frozen for the study; the same mapping applies to all arms.

| Arm | Route decision |
| --- | --- |
| Rules | Versioned deterministic rules on repository metadata and task fields; no semantic model |
| LLM router | One pinned LLM chooses the same finite route labels from the same approved task summary |
| Jev router | Pinned `jev-1.13.0` Choice over the same finite route labels and approved summary; code applies the predeclared abstain rule |
| Strong-always reference | Always use the strongest eligible coding model; measures whether routing is worthwhile at all |

Every arm uses the same hard rule for security-sensitive or unsupported requests. An `unclear` route, invalid answer, unavailable router, or threshold failure follows the same predeclared escalation path and is recorded as an abstention or failure, never silently counted as a correct classification. Router inference, escalations, retries, coding calls, and verification all count toward all-in cost and time. Under a documented provider-wide outage, preserve the original traces and rerun or exclude the **entire randomized task block** according to a rule frozen before the held-out run; failures specific to one arm remain in that arm's results. No agent sees another arm's trace or patch.

**Primary outcome:** verified completion within the fixed all-in budget. Completion requires the exact required and withheld evaluator commands to pass, no deletion or weakening of tests, and a blinded check of non-test acceptance criteria. An agent's statement that work is done has no authority. Record the exact commands, exit codes, and unedited outputs after each run. A non-run, timeout, or partial suite is incomplete, not green.

**Primary comparison:** Jev router versus LLM router on paired verified completion and all-in cost. Report the paired success difference with a task-clustered confidence interval and total cost per verified completion; also report paired cost ratios and absolute cost. Rules and strong-always are secondary baselines. The proposed confirmatory joint success rule is: the lower one-sided 95% task-clustered confidence bound for Jev-minus-LLM verified completion exceeds **−5 percentage points**, *and* the upper one-sided 95% bound for the Jev/LLM ratio of summed per-task all-in marginal costs is below **0.85**. Both conditions must pass. These margins are proposed decision preferences, not results; freeze or revise them before sizing and opening the held-out run. A 60–100-task exploratory run cannot be treated as proof of a small noninferiority margin.

For cost, record provider request IDs, billable input/output tokens, actual billed amounts when available, router calls, coding calls, retries, escalations, and verification compute time for every arm. Freeze the provider price schedule and a fixed local-compute hourly rate before the held-out run; report billed provider spend and modeled compute cost separately as well as their sum. Record human review minutes separately at a declared rate if a route requires them. If a material billed cost or usage item cannot be measured, mark the cost comparison **inconclusive** rather than treating it as zero. The task-clustered bootstrap resamples whole task blocks for both primary bounds; the analysis script, interval construction, and replicate handling are frozen before the held-out run.

Secondary outcomes: wall time, route distribution, misroutes relative to the best observed eligible route, harmful under-routing, abstention rate, reviewer workload, number of repair iterations, false “green” claims, tool/secret-policy violations, and failure rate by task stratum. Report all assigned tasks, including invalid responses and infrastructure failures, by original arm. Do not compute accuracy only on accepted Jev decisions without also reporting what fraction Jev accepted.

## Diagnostic comparisons

**Failed-test triage:** Freeze the *first* failure snapshot before any investigation. Compare rules, a pinned LLM, and Jev on `setup`, `regression`, `flaky`, `bad_test`, and `unknown`. Gold cause comes from controlled reruns in the same and clean environment, base-commit comparison, and blinded review. Report a confusion matrix, macro-F1, abstentions, and especially false `flaky` classifications. In a second paired run, give each diagnosis to the same repair agent and measure commands/time to the correct fix. A flaky label never skips a required test.

**Feature-plan selection:** One pinned generator creates two or three plans per task before any selector runs. Filter plans against exact constraints in code. Randomize plan order and give identical plans and pre-change facts to Jev, an LLM selector, and simple rules. Ask narrow independent Jev questions about requirement fit, untested assumptions, and likely integration risk, then combine them with fixed code; do not ask Jev to invent the plan. Blinded reviewers rate feasibility and completeness. The same implementation agent executes each **unique selected plan** from the same base commit and budget; use repeated implementations on a prespecified subset if affordable. Record whether the agent followed the plan. The independent evaluator measures verified completion. Report invalid-plan acceptance and downstream completion, not only preference agreement; retain intention-to-treat results when an agent deviates.

**Test-gap detection:** Freeze identical candidate criterion–test gap records, including withheld faults that the proposed tests miss. Let Jev, an LLM, and a static requirement checklist flag or rank those same candidates at a fixed review budget. A coding LLM or person, not Jev, proposes any new test. Report recall of material gaps, precision at the review budget, false alarms, and whether addressing flagged gaps lowers the rate of patches that pass existing tests but fail independent acceptance tests. Coverage tools and executed tests remain the authority for what actually ran.

## Staging, repetition, and analysis lock

1. **Bootstrap:** A future `coding_eval init` command creates bounded synthetic config, task, fixture, and output directories from empty state. `import-task` and `label` commands ingest real tasks and independent adjudications without hand-editing state. A dry-run lists exact tasks, model calls, network recipients, write locations, and caps. No hand-created database row or hidden source edit is required. Operator values live in validated configuration; code owns bounds. A complete fixture end-to-end run must pass before live use.
2. **Watched first run:** Make one watched, **synthetic** live Jev smoke call and inspect its model identity, request hash, response, audit, and failure behavior. Later commands reject missing, failed, or stale smoke evidence for the exact Jev model/configuration hash. Then execute one real task through one arm in an isolated checkout, with a hard cap on requests, tokens, time, and tool calls. Inspect raw audit and evaluator output. Execute its paired arms one at a time. No schedule or broad batch is enabled.
3. **Pilot:** Run 12–20 tasks across strata to validate instrumentation and estimate paired discordance, cost variance, and label ambiguity. This pilot can tune question wording, thresholds, and the sample-size calculation. It cannot support a general coding-quality claim.
4. **Freeze:** Save and hash corpus split, model IDs, prompts, Jev question/criteria order, route map, policy thresholds, evaluator commands, outcome definitions, retry behavior, and analysis script. Predeclare one primary comparison and any multiplicity correction for secondary tests. Leave held-out tasks untouched until this point.
5. **Held-out run:** Execute randomized paired task blocks. Analyze all assigned cases. Use task-clustered bootstrap confidence intervals for paired differences and inspect strata and failure cases. Do not stop early because results look good; pause only under predeclared safety or system-wide infrastructure conditions.
6. **Stability study:** Separately repeat identical Jev requests with local caching disabled and test harmless paraphrases and permuted Choice option order. Measure label, full-distribution, and policy-decision agreement. Do not mix these calls into the main causal comparison or mistake repeatability for correctness.

The current CLI has `init`, one-Choice `run`, `evaluate` capped at 20 cases, and `replay`; its existing live probe boots a maintenance/admin rubric. It does **not** run coding agents, create isolated checkouts, compare routes, or provide coding gold labels. Implement the study runner as a new, small CLI that reuses `run_one` only after constructing an allowlisted, sanitized state; ship `init`, `dry-run`, one-case `smoke`, bounded `pilot`, `run`, `analyze`, and `replay` commands. The new runner needs its **own append-only per-task and per-arm record** for rules/LLM/Jev routes, agent invocations, exact test commands and unedited output, budget use, failures, cost inputs, and terminal status. Record failed attempts visibly. A fixture or cached response is never substituted after a failed live call. [Harness CLI](../README.md), [prior non-coding results](LIVE_RESULTS.md).

Treat [Receptron's Laya](https://github.com/receptron/laya) as an optional **separate model arm**, not a Jev alias. Pin its model artifact, tokenizer, calibration, runtime, and adapter; test its shorter input limit and thresholds independently. Do not add it to the first paired study, where the causal variable is already the router. [Laya README](https://github.com/receptron/laya/blob/main/README.md).

## Decision after evidence

Adopt Jev only for the specific decision study where it beats a credible baseline on held-out outcomes at an acceptable abstention and error rate. A routing win does not authorize Jev to judge test success, secret safety, or plan feasibility. Publish the complete negative as well as positive results, with commands and unedited output for every “green” or “verified” claim. If the results are neutral, retain exact rules and the coding LLM without an extra Jev call.
